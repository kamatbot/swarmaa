# Watch host services

The memo service must run on macOS; it rejects memo operations on other platforms so `stored_on: mac` identifies the actual host. Memo chunks are 128 KiB except the final chunk; uploads are limited to 20 MiB and 20 memos per thread, including incomplete uploads. Uploads are retained until explicitly deleted. PostgreSQL retains chunks and the manifest; stored M4A files reside under `SWARMAA_MEMO_DIR` (default `~/.swarmaa/memos`) in a SHA-256-of-tenant-ID directory, then thread UUID and memo UUID. The tenant hash supports existing text tenant IDs without using them as paths. The service creates directories with mode 0700 and files with mode 0600, and rejects existing symlink components and non-private memo directories. The configured root and its ancestors must be controlled by the owner; a malicious local process with the same UID is outside this isolation boundary. Files and their containing directory are synced before a stored receipt; retrying the same completed upload reconstructs and saves the verified bytes again after an uncertain result. Back up and remove both database and files according to the owner's retention policy.

RetireOdds requires `SWARMAA_RETIREODDS_PRINCIPALS` (comma-separated principal UUIDs), `SWARMAA_RETIREODDS_ORIGIN` (HTTPS or literal 127.0.0.1 HTTP origin), `SWARMAA_RETIREODDS_USER_ID`, and `SWARMAA_RETIREODDS_COOKIE_FILE` (absolute path to an owner-owned 0600 file containing the cookie header). Credentials stay on the host. Preview is review only; confirmation requires the returned token and a stable confirmation UUID. On an uncertain response, use the same request or confirmation ID or get the review; do not invent a new confirmation. A confirmed receipt comes from RetireOdds, not an agent approval. Configuration changes invalidate old review bindings.
