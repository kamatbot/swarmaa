Swarmaa guide

One swarm for Claude Code, Codex, Antigravity and Grok: they share memory and chats, and any of them can hand work to the others.

1The idea

Swarmaa runs on your Mac. It keeps a task queue, shared memory and a log of every chat. Three background workers — Claude, Codex and Antigravity — pick up tasks and run them in a sandbox. The notch shows who is live, what is running and how much quota each service has left.

You never talk to Swarmaa directly. You talk to whichever agent you are already using, and it uses Swarmaa’s tools for you.

2Ask for work

In any harness, just say what you want. Name a service only if you care which one does it.

“Have the swarm review the auth changes in pathodds.”

“Ask Codex to add tests for the grader, starting from feat/math-path.”

“Get Antigravity to review this PR’s diff.”

“Fan this out: Claude fixes the bug, Codex writes the tests.”

You wantAgent sendsWho does it

The agent tells you the task ID. Ask “how is task 3511 going?” to check, or “continue 3511: also handle empty input” to add an instruction. Tasks stop after 60 minutes.

3Edits come back as branches

Every code task runs in its own copy of the repo (a git worktree), so several agents can work on one project at once without touching your checkout. The worker can edit files and run commands, builds and tests inside that copy. When it finishes, Swarmaa commits the result to a local branch:

swarma/<service>/<task id>     e.g. swarma/codex/8855687b

Nothing is pushed, merged or deployed. Review and merge it yourself, or ask your agent to:

git log --oneline main..swarma/codex/8855687b
git diff main...swarma/codex/8855687b
git merge swarma/codex/8855687b

Continuing a task adds commits to the same branch. If a run crashes, the next attempt picks up its unfinished edits.

4Routing rules

Open the menu bar icon → Settings → Swarmaa → Routing.

  • Order — drag rows; the top service is tried first.
  • Sliders — switch away from a service once its 5-hour or weekly use passes this level.
  • Review / Research / Edit — which kinds of task each service may take.
  • If no service qualifies — use whichever has the most quota left, or wait.

The line at the top shows who gets the next task of each kind, and why. Defaults: Claude until 90%, then Codex until 95%, then Antigravity until 95% (reviews and edits only — it can’t reach outside the project, so no research).

5Shared memory

Anything one agent saves, every other agent can find — per project.

“Remember for pathodds: grading tolerances live in grader/config.ts.”

“What do we know about the math-path rollout?”

Notes and observations are shared right away. Decisions and preferences wait for your approval before agents treat them as settled. Approved lessons show in the notch for review.

6Shared chats and /swarm

Chats from Claude Code, Codex and Antigravity are logged automatically, and every swarm run is logged as a chat titled [swarm] …. Any agent can list them, read them, or pick one up.

HarnessType
Claude Code/swarm
Codex$swarm
Antigravity/swarm (run /skills reload once if it’s missing)
  • /swarm — live workers, queue, and recent swarm runs with their branches.
  • /swarm 3511a624 — one run: what was asked, the answer, the branch and diff.
  • /swarm continue 3511a624 also add tests — continue it.
  • /swarm run review the payment flow — start a new task in this project.

Resume a run in the terminal. Claude edit runs and Codex runs can be continued in the CLI. The run’s last line shows the command:

  • Claude: cd ~/Projects/app && claude --resume <id>
  • Codex: cd ~/Projects/app && codex resume <id>

Run it from the project folder. Claude read-only runs and Antigravity runs can’t be resumed this way.

Swarm runs still don’t appear in the Claude or Codex desktop app sidebars — those apps only list chats they started themselves. Use /swarm or the resume command instead.

7Grok

Grok connects over the internet to https://api.swarmaa.com/mcp. The first time, it opens a Swarmaa sign-in page: sign in with your passkey and approve. After that, Grok can check status, hand out tasks, read results and continue chats from any harness — it’s a good “front desk” from your phone.

Grok doesn’t run code itself through the swarm; it sends work to Claude, Codex or Antigravity. The instructions to paste into Grok are in clients/grok/INSTRUCTIONS.md.

8What it won’t do

  • No pushing, merging, deploying, messaging or payments by swarm workers — you (or your interactive agent) do that.
  • Workers can’t read your other chats, SSH keys, cloud credentials or files outside the project.
  • No direct agent-to-agent messages — they coordinate through tasks, continuations and shared memory.
  • Results are marked unverified until you review them.

9Troubleshooting

Is it running?

curl -s http://127.0.0.1:8787/healthz
launchctl list | grep swarma

Restart the service or a worker

launchctl kickstart -k gui/$(id -u)/com.swarma.service
launchctl kickstart -k gui/$(id -u)/com.swarma.bridge.codex

Logs

~/Projects/swarma/.local/logs/ — service.log, bridge.claude.log, bridge.codex.log, bridge.agy.log.

A task is blocked

Ask your agent to read the task: blocked tasks say why (no git repo, bad branch name, provider disabled by routing, or a command the sandbox refused). Fix it and continue the task.
