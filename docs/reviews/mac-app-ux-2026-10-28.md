# Mac app UX review (Codex, 2026-10-28)

Read-only review of the main window at NotchTrader 53e5fc7, now at `Mac-app/` in this repo. File paths below are relative to `Mac-app/Sources`.

Read-only review of clean app commit `53e5fc7`, both briefs, seven fixtures and service source `4acaef2`. No app launch, tests or service calls. App filenames refer to `Mac-app/Sources`; service references are in `/Users/mk/Projects/swarma`.

Ranked by impact:

1. **P1 — Accessibility-window cause NOT FOUND.** `TeamsWindow.swift:14` uses a retained, titled NSWindow/NSHostingView. Checked root modifiers, plist, scene setup, activation policies and NotchPanel; no root hiding found, and notch non-key overrides do not apply. [Apple documents default NSWindow accessibility support](https://developer.apple.com/documentation/appkit/nsaccessibilityprotocol) (retrieved 2026-10-28). Next diagnostic: match the installed binary/PID to WindowServer, then compare AXWindows/roles/children with NSApp.windows in Dock/accessory modes. Adding control labels alone would not explain zero windows.

2. **P1 — Real questions disappear; answers render empty.** `SwarmaTeamsClient.swift:379` expects object bodies, but service `src/core/swarms.ts:1542` stores string prompts with question references; :914 builds string answers. Consequently `ThreadView.swift:147` omits question controls. The implemented owner_required notice is unreachable through these real messages. Hydrate questions using `ref.question_id`, render string answers, and test nonempty service-shaped fixtures.

3. **P1 — Recent history is inaccessible.** `TeamsModel.swift:261` treats default thread_read as latest; service `src/core/teams.ts:610` returns the oldest 50. `ThreadView.swift:18` then requests messages before seq 1. Fetch/page forward to the latest tail, then page backward for older history.

4. **P1 — Composer risks wrong-thread sends and lost drafts.** `ThreadView.swift:452` never uses threadID or keys editor state by thread; `TeamsModel.swift:307` sends to current selection. Switching threads carries the draft across. Typing remains enabled during sending; failure at `ThreadView.swift:491` overwrites newly typed text. Bind drafts/sends to explicit threads, preserve concurrent typing, retain idempotency keys across uncertain retries, and restore editor focus after mouse Send.

5. **P1 — Resolve fails for normal app identities.** `TeamsModel.swift:217` calls task_resolve, but service `src/core/swarms.ts:1205` requires admin. `SwarmaClient.swift:297` misleadingly says “can’t review lessons.” Running rows also offer resolution although service :1221 rejects running tasks. Resolve this brief/service permission conflict through scoped owner authorization, without desktop admin credentials; gate controls by permission/status and show task-specific errors.

6. **P1 — First-use discovery dead end.** `AppDelegate.swift:1514` opens Settings on Dock reopen. Open Swarmaa exists only in `StatusItemController.swift:362`, whose icon is absent in default Dock mode. Once reached, Home says “Nothing needs you”; creation exists only under Agents (`TeamsWindow.swift:85`) and disappears after the first agent. Add a persistent main-window entry and bottom Create agent actions on empty Home and populated Agents.

7. **P1 — Offline looks empty or silently stale.** `TeamsModel.swift:155`, :184 discard failures, clearing channels/swarms/usage/tasks or retaining stale attention. Stream retries are invisible (`SwarmaTeamsClient.swift:729`); terminal 401 is swallowed (`TeamsModel.swift:378`). Home Refresh reloads only tasks (`TasksViews.swift:40`). Preserve last-known data with stale/error indicators, expose reconnect/auth status and offer full refresh.

8. **P2 — Unread clears unseen messages.** `TeamsModel.swift:391` considers the selected thread open even while Home/Tasks is displayed; :422 clears badges for every principal’s thread.read. :298 advances acknowledgment before request success. Gate reads by actual thread visibility, respect principal/sequence and retry failures. `ThreadView.swift:31` also pulls readers to the bottom on every new message; autoscroll only when already near the bottom.

9. **P2 — Accessible names/state are incomplete.** `TeamsWindow.swift:130` quota buttons expose initials; :135 gear relies on glyph/help; :334 Instructions editor lacks label association. `ThreadView.swift:256`, :464, :475 need explicit Open swarm/editor/Send names. `TasksViews.swift:183` gives every checkbox the same Resolve/Unresolve name. Add contextual labels/values, editor associations and selected/expanded states.

10. **P2 — Pointer-only actions; links miss cards.** `TasksViews.swift:201` opens questions/swarms only by double-click; task rows lack Review/Retry actions. Notch opening lives at `NotchWindowController.swift:1575`, while `ProviderRing.swift:359` exposes no press action/button role. `TeamsModel.swift:199` selects only a thread; `SwarmaTeamsClient.swift:842` discards swarm identity. Add keyboard-accessible actions and retain target identity through loading and scrolling.

11. **P2 — Blank history and endless spinner.** `ThreadView.swift:22` lacks initial thread loading/error UI; failed reads leave blank history after the alert. `TeamsModel.swift:368` suppresses swarm-fetch errors, leaving `ThreadView.swift:517` spinning indefinitely. Sidebar search can leave an unexplained empty List (`TeamsWindow.swift:189`). Give each explicit loading, empty, error and Retry states.

12. **P2 — Tasks controls mislead.** `TeamsTasks.swift:176` always regroups into fixed sections, so Newest and By state display identically. `TeamsModel.swift:187` loads only running tasks: Retry can hide a requeued task until claimed. Make sort visibly distinct and include queued progress. `SwarmaTeamsClient.swift:621`, :637, :641, :678 ignore pagination, hiding older search matches and undercounting questions; follow cursors or expose Load more.

13. **P2 — Setup permission probe is unreliable.** `TeamsTasks.swift:201` treats every REST 404 as permission granted, including absent tools; MCP not_found becomes badResponse (`SwarmaClient.swift:488`). All 403s become owner-required. Preserve structured codes, distinguish tool/resource absence from permission failures, and publish checklist results as probes finish.

14. **P2 — Runner changes erase model selection.** `ThreadView.swift:101` constructs provider/effort without model, so changing effort silently drops an existing model. Preserve compatible models, expose supported model choices and prevent duplicate updates while saving.

15. **P2 — Thumb reach, sizing and large text.** `TeamsWindow.swift:114`, :187 and `ThreadView.swift:60` place rail/search/runner controls high; row/card actions float with content. Move interactive toolbars/actions below content. `ThreadView.swift:521` fixes detail at 520×460; use content-driven sizing with bounded scrolling. Fixed 9–13pt fonts, single-line rows and unconstrained chip measurement (:436) risk clipping; use scalable fonts and constrained wrapping. Palette adapts to light/dark, but small colored text needs contrast verification.

16. **P2 — Redraw risk and misleading copy.** `TeamsModel.swift:419` reloads all scopes serially per task event; shared model observations repeatedly parse Markdown (`ThreadView.swift:166`). Coalesce scoped refreshes and cache parsing; no measured hang is claimed. `TasksViews.swift:79` Review silently copies a command: label it “Copy review command” and confirm copying. `TeamsWindow.swift:126` says Flows but lists swarms: rename or implement flows.

Return/Shift-Return handlers and create-sheet Return/Escape exist. Actual AX enumeration, tab order, Cmd-W, other-sheet Escape, focus, appearance/large-text rendering and performance remain runtime-unverified. No production demo data found.
